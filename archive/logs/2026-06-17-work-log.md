## 1. WAV→VA/VAD JSON出力 Stage 1 疎通CLI実装

### 目的

研究用評価に入る前に、WAVファイルからVA/VAD形式のJSONを出力する縦導線を段階的に作る。

今回の対象は「WAV→出力JSONまで通る」Stage 1 のみ。数値の意味づけや研究評価は行わず、未学習headでも明示的に許可された場合だけ疎通確認として出力できる状態にする。

### 実行前の状態

- `vad_downstream/data.py` は `<prefix>.npy`、`<prefix>.lengths`、`<prefix>.vad` を読み、padding済みbatchを返せる状態だった。
- `vad_downstream/model.py` には `VADRegressionHead` と `Emotion2vecVADModel` があり、encoderが返したframe-level特徴量からVA/VADを出せる状態だった。
- `vad_downstream/training.py` にはCCC lossと1epoch学習helperが実装済みだった。
- WAVファイルパスを直接受け取り、VA/VAD JSONを出すCLIは未実装だった。

- 実emotion2vec checkpointの読み込みは今回対象外。

### 実施内容

`vad_downstream/inference.py` を新規追加した。

主なCLI引数:

- `--wav`: 入力WAVファイル。
- `--model-dir`: Stage 2用に予約。Stage 1の組み込みencoderでは指定時に未実装エラー。
- `--checkpoint`: Stage 2用に予約。Stage 1の組み込みencoderでは指定時に未実装エラー。
- `--target-dim 2|3`: VA 2次元、またはVAD 3次元を選択。
- `--head-checkpoint`: `VADRegressionHead` のcheckpoint。
- `--allow-random-head`: 未学習headでの出力を明示的に許可。
- `--output`: JSON出力先。未指定時は標準出力。
- `--device auto|cpu|cuda`: 推論デバイス。

Stage 1用の `Stage1AudioFeatureEncoder` を追加した。

- 実emotion2vecではなく、WAV波形から簡易統計量を作る決定的なplaceholder encoder。
- これは研究用特徴量ではなく、`Emotion2vecVADModel` と `VADRegressionHead` まで配線を通すためだけの実装。
- 実checkpoint読み込みは `build_stage1_encoder()` で明確にStage 2未実装として扱う。

head checkpointの扱いを固定した。

- `--head-checkpoint` がない場合、原則 `ValueError`。
- `--allow-random-head` が指定された場合のみ、未学習headでJSON出力を許可。
- 出力JSONの `random_head` に `true` を入れ、未学習出力であることを明示。
- `head_checkpoint` には指定path、未指定時は `null` を入れる。

JSON形式を固定した。

VA 2次元:

```json
{
  "labels": ["valence", "arousal"],
  "prediction": {
    "valence": 0.0,
    "arousal": 0.0
  },
  "head_checkpoint": null,
  "random_head": true
}
```

VAD 3次元:

```json
{
  "labels": ["valence", "arousal", "dominance"],
  "prediction": {
    "valence": 0.0,
    "arousal": 0.0,
    "dominance": 0.0
  },
  "head_checkpoint": null,
  "random_head": true
}
```

実際のJSONには上記に加えて `wav` と `target_dim` も含める。

WAV読み込みを実装した。

- 標準ライブラリ `wave` と `numpy` で読み込み。
- 16kHz monoのみ対応。
- 8-bit、16-bit、32-bit PCMをfloat tensorへ変換。
- 空音声、非16kHz、非mono、未対応sample widthは明確な `ValueError`。

#### Stage 2. 実emotion2vec checkpoint疎通

目的:

- Stage 1で固定したCLI表面を維持したまま、placeholder encoderではなく実emotion2vec checkpointを読み込んでWAVからframe-level特徴量を抽出する。
- 研究評価ではなく、まず「実checkpointでWAV→VA/VAD JSONまで落ちずに通る」ことを確認する。

実装範囲:

- `scripts/extract_features.py` と同じ方式でfairseq user moduleを読み込む。
- `--model-dir` をfairseq user module pathとして使う。
- `--checkpoint` を実emotion2vec checkpoint pathとして使う。
- `fairseq.utils.import_user_module(...)` を通す。
- `fairseq.checkpoint_utils.load_model_ensemble_and_task([checkpoint])` でmodel、cfg、taskを読み込む。
- modelを `eval()` にする。
- `--device auto|cpu|cuda` に従ってmodelと入力tensorを移動する。
- `task.cfg.normalize` がtrueの場合は、`scripts/extract_features.py` と同じく `F.layer_norm(source, source.shape)` を適用する。
- `model.extract_features(source, padding_mask=None, mask=False, remove_extra_tokens=True)` 互換でframe-level特徴量を取得する。
- 取得した特徴量を既存の `VADRegressionHead` に渡す。
- Stage 1と同じJSON形式で出力する。

入力WAV契約:

- 16kHz monoのみ対応。
- sample rateが16000Hzでない場合は明確なエラー。
- channelsが1でない場合は明確なエラー。
- resamplingやstereo mixdownはStage 2では自動実行しない。

CLI上の期待挙動:

- `--model-dir` と `--checkpoint` の両方を指定した場合、実checkpoint loaderを使う。
- `--model-dir` または `--checkpoint` が片方だけ指定された場合は、引数不足として明確なエラーにする。
- `--head-checkpoint` がない場合は、Stage 1同様に `--allow-random-head` がない限り拒否する。
- `--allow-random-head` を指定した実checkpoint疎通は可能。ただし出力は研究結果ではなく配線確認。

検証方針:

- 利用可能なcheckpointがある場合:
  - `scripts/test.wav` またはユーザー指定WAVでCLIを実行する。
  - JSONに `labels`、`prediction`、`head_checkpoint`、`random_head` が含まれることを確認する。
  - `--device cpu` で最低限動くことを確認する。
  - CUDA環境がある場合のみ `--device cuda` または `--device auto` を確認する。
- checkpointがない場合:
  - 実checkpoint疎通は未実行としてログに残す。
  - unit testはfairseq実ロードに依存させず、loader部分をmockまたはdummyで分離して確認する。

Stage 2ではまだやらないこと:

- headの研究用学習。
- checkpoint保存workflow。
- validation/evaluation metricの整備。
- resamplingや音声前処理の自動化。
- dataset単位のWAV batch推論。
- emotion2vec本体fine-tuning。

完了条件:
